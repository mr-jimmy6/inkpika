## 各类设备的兼容工作

### 1. PW2：工程基线

- **共享实现**：Go 1.23.12、`CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=5`，POSIX sh / BusyBox，ES5 和系统字体，无额外设备运行时。
- **系统集成**：Mesquite/WAF 应用 `com.inkpika.app` 与 `local-port-access`；安装于 `/mnt/us/extensions/inkpika`，文档目录 `/mnt/us/documents/InkPika`；无线传书和配置使用独立防火墙链。本次已验证该 PW2 的安装、二进制运行、WAF 配置／云端页面及配对服务。
- **菜单措施**：KUAL 导航项不设置 `refresh: true`，避免进入子菜单触发全局重载；状态／同步及服务动作仍可显式刷新。本次原版 KUAL 已实测中英文子菜单停留、逐级返回和配置设置入口。KUAL 内部状态使用 ASCII；通过 `/proc/PID/cmdline` 判断服务；可选导航补丁只匹配指定 KUAL 原始 JAR，不包含在客户端 ZIP。
- **部署工具**：通过 tar / SSH 安装，使用白名单、SHA-256、进程检查、同盘替换及程序备份；已在本次 PW2 安装中执行并核对设备端文件摘要。
- **网络实现**：OSS、QingStor、S3、Azure Blob、SOCKS5 和附加 CA。本地协议测试通过；该 PW2 的真实 OSS HTTPS、列举与抽样读取通过。其余真实平台、代理与私有 CA 仍待验证。
- **本次界面调整**：配置信息与手动连接测试移到配置设置，版本和 UTC 打包时间放在表格末尾；专用本机接口使用独立令牌、Host / Origin 校验，与传书和 LAN 配置编辑隔离。中英文配置界面均在该 PW2 实测，并检查浏览器演示。
- **待验证 / 限制**：其他布局、显式同步／状态刷新后的导航、下载 / 同步、索引 / 阅读、大文件、休眠和断网恢复。服务启动后的首次菜单刷新可能早于启动完成，可重新进入读取状态。Go 1.23 已退出官方安全维护；提高工具链版本需重新评估内核要求。

源码：[构建](../scripts/build.sh)、[WAF 注册](../extensions/inkpika/register-ui.sh)、[WAF 权限](../extensions/inkpika/ui/config.xml)、[TLS](../internal/cloudhttp/client.go)、[菜单](../internal/syncer/menu.go)、[防火墙](../cmd/inkpika/transfer_firewall.go)、[部署](../scripts/deploy-device.sh)、[可选补丁](KUAL_NAVIGATION.md)。

### 2. 与 PW2 接近的后续平台

共享实现包含 S3 / SOCKS5 / 附加 CA，并采用 `inkpika` 路径、`com.inkpika.app` 和版本/打包时间元数据；该类别尚无对应的专门适配或真机验证，程序启动、网络、证书、签名与配置界面均待验证。

范围：Voyage、基础款 2014 / 2016（KT2 / KT3）、PW3、Oasis 1 / 2；其他机型运行 5.16.3 之前固件时也需参考本类的运行环境检查。

- **判断**：候选兼容，优先验证。
- **已有共享兼容措施**：静态 ARM 程序不依赖设备动态 glibc；后台不直接访问屏幕驱动、触控节点或物理翻页键；使用系统 WAF 渲染页面。没有按机型拒绝启动的代码。
- **专门适配与验证**：尚未为这些机型添加专用实现，也没有对应真机测试；不能把 PW2 的结果复制到这些型号。
- **待办 / 问题**：核实内核、程序启动、Mesquite 路径、应用注册表和回环权限；检查 KUAL 动态菜单、中文字体、触控、图书索引与服务停止。先使用设备正常工作的 KUAL，不直接套用 PW2 导航补丁。

源码：[构建](../scripts/build.sh)、[网页入口](../extensions/inkpika/open-ui.sh)、[主程序](../cmd/inkpika/main.go)、[菜单](../internal/syncer/menu.go)。

### 3. PW4、基础款 2019、Oasis 3 与较新固件

共享实现包含 S3 / SOCKS5 / 附加 CA，并采用 `inkpika` 路径、`com.inkpika.app` 和版本/打包时间元数据；该类别尚无对应的专门适配或真机验证，程序启动、网络、证书、签名与配置界面均待验证。

- **判断**：候选兼容；固件版本需要单独记录。
- **已有共享兼容措施**：沿用无 C 依赖的静态 ARM 后台、POSIX 脚本和 ES5 页面。社区工具链将 **5.16.3 起的固件**区分为 hard-float 平台；本项目没有动态 C 库依赖，因此这个变化本身不足以证明程序不兼容，也不自动意味着必须重编译。
- **专门适配与验证**：尚无按 hard-float 固件划分的启动、注册或防火墙分支，未在本类设备验证现有二进制。
- **待办 / 问题**：先验证程序能否运行，再确认 WAF 的命令参数、注册表结构、权限和 KUAL 版本；检查无线传书使用的 `iptables`、`wlan0` 与私有 IPv4 访问规则。若实际采用不同接口，应按设备证据适配。

源码：[构建](../scripts/build.sh)、[应用注册](../extensions/inkpika/register-ui.sh)、[防火墙](../cmd/inkpika/transfer_firewall.go)。固件分界参考[KOReader 工具链说明](https://github.com/koreader/koxtoolchain#notes)。

### 4. PW5 / PW6、Signature 与基础款 2022 / 2024

共享实现包含 S3 / SOCKS5 / 附加 CA，并采用 `inkpika` 路径、`com.inkpika.app` 和版本/打包时间元数据；该类别尚无对应的专门适配或真机验证，程序启动、网络、证书、签名与配置界面均待验证。

- **判断**：理论可行，需完整真机验证。
- **已有共享兼容措施**：未绑定 PW2 的屏幕驱动或芯片；网页通过 WAF 运行，下载与云平台协议由独立 Go 模块实现；地址发现遍历网卡，优先选择 Wi-Fi 私有 IPv4。
- **专门适配与验证**：尚无这些设备的专用构建、启动方式或布局；无本项目真机结果。
- **待办 / 问题**：核实内核与 ARM 执行环境，不能仅凭 CPU 名称认定必须用 ARM64；现有打包器只接受 32 位 ARM ELF。检查新固件的 WAF、KUAL、网络规则、屏幕缩放、书库索引和休眠恢复。地址发现可遍历网卡，但防火墙跳转仍固定为 `wlan0`。

源码：[打包目标](../scripts/package.py)、[网卡地址发现](../internal/transfer/server.go)、[防火墙](../cmd/inkpika/transfer_firewall.go)、[网页样式](../internal/web/assets/style.css)。

### 5. Scribe 2022 / 2024 与 Colorsoft 系列

共享实现包含 S3 / SOCKS5 / 附加 CA，并采用 `inkpika` 路径、`com.inkpika.app` 和版本/打包时间元数据；该类别尚无对应的专门适配或真机验证，程序启动、网络、证书、签名与配置界面均待验证。

- **判断**：理论可行，需增加大屏 / 彩屏环境的验证。
- **已有共享兼容措施**：后台没有屏幕颜色、手写笔或机型尺寸依赖；HTML 页面由设备框架渲染，使用黑白高对比样式；手机端页面有窄屏布局，二维码本地生成。
- **专门适配与验证**：没有针对 Scribe 大屏、彩色屏幕或手写功能的专用适配；没有对应真机证据。手机窄屏预览不等于这些 Kindle 的屏幕验证。
- **待办 / 问题**：除上一类的系统集成检查外，验证固定像素字号、820px 内容宽度、二维码大小、点击区域、方向变化和系统书库索引。项目负责传书，不提供 Scribe 笔记同步、手写集成或额外阅读格式支持。

源码：[书架样式](../internal/web/assets/style.css)、[连接页样式](../internal/transfer/assets/style.css)、[连接与配对](../internal/transfer/server.go)。

### 6. 更新平台或特殊系统

共享实现包含 S3 / SOCKS5 / 附加 CA，并采用 `inkpika` 路径、`com.inkpika.app` 和版本/打包时间元数据；该类别尚无对应的专门适配或真机验证，程序启动、网络、证书、签名与配置界面均待验证。

- **已有措施**：保留现有共享代码，没有据型号名称增加未经验证的设备分支。
- **专门适配与验证**：尚未完成。
- **待办 / 问题**：先收集不含序列号和凭据的型号、固件、内核、执行架构、KUAL / WAF 与文件系统信息。确认运行环境后决定能否复用现有包、是否需要额外架构构建或不同启动入口。前代平台结果不能作为本类验证证据。

### 7. Kindle Touch、PW1 与更早设备

共享实现包含 S3 / SOCKS5 / 附加 CA，并采用 `inkpika` 路径、`com.inkpika.app` 和版本/打包时间元数据；该类别尚无对应的专门适配或真机验证，程序启动、网络、证书、签名与配置界面均待验证。

- **判断**：需要独立移植评估，不推荐直接使用当前安装包。
- **已有共享兼容措施**：`GOARM=5` 的低指令集要求、无 C 依赖、POSIX 脚本和 ES5 页面可减少部分依赖，但不能解决内核与系统框架差异。
- **专门适配与验证**：没有为旧内核添加运行时补丁，也没有非触屏导航或旧应用框架实现。
- **待办 / 问题**：Touch / PW1 常见平台为 Linux 2.6.31，低于 Go 1.23 的官方下限 2.6.32；这表示超出受支持范围，不是本项目实测启动失败。K1、K2、DX / DXG、Keyboard 和早期非触屏基础款还涉及更老内核、不同输入与应用框架，部分机型没有 Wi-Fi。需重新评估运行时、入口与网络，不只是调整 `GOARM`。

依据：[Go 1.23 Linux 要求](https://go.dev/doc/go1.23#linux)、[社区设备工具链分类](https://github.com/koreader/koxtoolchain#notes)、[旧平台工具链内核基线](https://github.com/benoit-pierre/crosstool-ng/blob/34844bc8e985ad1ba26b072a5b58264967072e19/samples/arm-kindle5-linux-gnueabi/crosstool.config)。

## 新增适配与验证记录的方法

1. 更新所属类别：记录具体改动、涉及源码、解决的问题，以及仍未覆盖的固件 / 功能。没有专门改动时注明复用哪些共享措施。
2. 先运行对应的本地回归、检查和构建；将结果标为自动验证，不记作设备验证。
3. 真机验证至少记录程序启动、KUAL、三个网页入口、配对配置、双向传书、云端下载与同步、原生书库索引、服务启停及休眠恢复的实际结果；未执行项目写明未测。
4. 将型号、固件、内核、KUAL、日期、构建哈希和功能范围写入 [DEVICE_VALIDATION.md](DEVICE_VALIDATION.md)，再更新本文顶部的已验证设备表。部分功能通过不能写成全功能通过。
5. 同步更新中英文 README 与介绍页的支持表述。源码引用使用仓库相对链接；不记录真实序列号、网络地址、账号、令牌或设备截图。

优先验证路线：PW3 / KT3 → PW4 → PW5 → PW6 → Scribe / Colorsoft。Signature、Kids、容量和地区变体在底层硬件与固件相同时可参考对应类别，但不能自动获得已验证状态。
