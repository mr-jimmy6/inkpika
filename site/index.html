Scenario 01 · Phone → Kindle

Scan to send a book from your phone.

Requires InkPika installed and both devices on the same Wi-Fi.

  1. Open the entry on KindleKUAL → InkPika → Wireless transfer [web].
  2. Scan to pair your phoneScan the device QR code and open the transfer page in your phone browser.
  3. Choose books and uploadSelect multiple files. After saving and indexing, open compatible books from the Kindle library.

Daily transfers need no computer, cloud account or extra phone app. You can also download Kindle books back to your phone.

See wireless transfer steps

Scenario 02 · Paper → Agent → Cloud library → Kindle

Translate a paper, then sync it to read.

Requires your own Hermes or similar agent and a configured OSS / QingStor / S3-compatible library.

  1. Let your agent prepare the bookFor example, send a paper through Lark so your agent can translate it and create a Kindle-compatible ebook.
  2. Put the finished book in your cloud reading listAn agent with the tools and your authorization uploads it to your bucket's root sync/ folder.
  3. Select Start sync on KindleInkPika checks and downloads missing or updated books. Read them locally with the native reader.

Your external tools handle translation, ebook creation and uploads. InkPika checks and downloads; you trigger each sync.

Public clouds and your own NAS

Choose where your library lives.

Connect to your own object storage.
Choose books in the library or sync through KUAL.

Connect directly to familiar public clouds.

Supports Alibaba Cloud OSS, QingStor, Amazon S3, Volcengine TOS, Microsoft Azure Blob, IBM Cloud Object Storage, Google Cloud Storage, Tencent COS, Cloudflare R2, Backblaze B2 and DigitalOcean Spaces. Connect your own S3 library; R2 / B2 free allowances may suit small libraries.

Choose the platform or Custom S3 / NAS under Storage platform, then enter the bucket, region and credentials. TOS, IBM, Google and Tencent use S3-compatible interfaces. Azure uses native Blob APIs with a container, account name and Account Key. The Azure account key grants broad permissions; this client performs only reads. R2 region is auto; enter its HTTPS S3 API Endpoint from the console.

Connect a NAS through S3.

Choose Custom S3 / NAS and enter its HTTPS S3 endpoint, bucket, signing region and read-only credentials, typically with path-style addressing. Upload books to an object storage bucket; an ordinary shared folder does not automatically become an S3 library.

  • Garage: open-source S3 object storage.
  • SeaweedFS: provides an S3 interface and supports single-node deployment.
  • MinIO / AIStor: AIStor Free is free for a single node under a commercial license. The original MinIO open-source edition is no longer maintained; avoid it for new deployments.

These are software examples; specific versions have not been tested together. Kindle must be able to reach the NAS. S3 provides no NAT traversal and does not include WebDAV. Upload with NAS tools or an external S3 client.

Optional SOCKS5. HTTPS verification stays on.

All object storage supports socks5://HOST:PORT or socks5h://USER:PASSWORD@HOST:PORT; URL-encode special characters. Destination names are resolved by the proxy. Proxy failures return errors with no direct fallback. Saved proxies are hidden; blank keeps them and an explicit checkbox clears them. Only object storage uses the proxy; wireless transfer and settings do not. SOCKS5 authentication itself is unencrypted; object storage still uses HTTPS.

For a NAS with a private CA, copy a PEM CA certificate to Kindle and set Additional CA certificate path. Certificate and hostname verification remain enabled. Read the full connection guide.

Implementation and test records: InkPika includes OSS, QingStor, S3 and Azure Blob adapters, SOCKS5 and additional CA support. Feature and device test results are maintained in the validation record. See Feature and device validation record.

One 5 MB book per month: what does a year cost?

Starting empty, upload and retain one 5 MB book (5,000,000 bytes) at the beginning of each month and download each once: about 60 MB stored at year end, 0.39 GB-month accumulated storage and 0.06 GB downloads. Assume 100 LIST and 200 GET/HEAD requests per month, including book downloads, plus 12 PUTs a year. External tools upload; the Kindle client is read-only. Standard storage and approximate decimal GB are used.

You may also want to know

Before you start reading.

More configuration and troubleshooting guidance
is in the project documentation.

Which Kindles are supported? Is jailbreak required?

InkPika targets Kindle devices across generations and requires jailbreak and KUAL. PW2 / firmware 5.12.2.2 is the engineering baseline. For device requirements, implemented measures and remaining work, see the compatibility documentation. The project includes no jailbreak tools.

Do I need a public-cloud account?

Wireless transfer needs no cloud account: connect your phone, computer and Kindle to the same Wi-Fi. Cloud library and sync require your own object storage bucket: OSS, QingStor, AWS S3, TOS, Azure Blob, IBM, Google, Tencent, R2, B2, Spaces or an S3 service on your NAS. The project includes no book sources.

How do I upload books? Is sync scheduled?

Upload through a cloud console, an agent with appropriate tools and authorization, or an API. InkPika only lists, reads and downloads. Select Start sync in KUAL to check and download missing or updated books from sync/ ; it is not a scheduled job. The graphical library browses the configured scope for on-demand downloads.

Do I need a different reader?

No. Books are saved locally and appear in the native reader after system indexing. InkPika handles transfer and downloads; readability depends on file format, DRM and native device support.

Which ebook formats are supported?

Default transfer formats are AZW, AZW3, MOBI, PRC, PDF and TXT. Adjust the allowlist in Settings; it applies to wireless transfer, cloud library and KUAL sync. Actual reading support depends on Kindle. The project does not convert formats or handle DRM.

Will downloads or sync overwrite or delete my books?

Wireless transfers number duplicate filenames; manual cloud downloads never overwrite existing books. Sync updates only registered copies after integrity and remote-version checks, preserving old files on failure. Cloud deletion never deletes local books.

Why has my book not appeared on the home screen?

Kindle still needs to index a saved file. Return to Downloaded or All items and wait, checking that the format is supported. Keep Kindle awake during transfer; sleep can disconnect Wi-Fi. Saved to Kindle means the file is saved, not that indexing is finished.

Is it free? What has been tested?

InkPika is free under the MIT license. Object storage may incur storage, request and traffic fees. Feature and device test results are maintained separately. See the device validation record.

Do services stay running afterward?

Leaving a web window does not stop its service. In KUAL → InkPika → Background services, stop wireless transfer, cloud library and settings independently. None starts at boot by default. Use paired transfer and settings on a trusted LAN.
